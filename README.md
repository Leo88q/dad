# Рядом

Мини-приложение **MAX** для спокойных совместных занятий пожилого человека и близкого, с браузерным режимом разработки. Интеграция написана и проверяется локально с подменённым Bridge; публикация и проверка в настоящем MAX ещё не выполнены. **Текущий статус — тестовый пилот, не готовый публичный сервис.**

## Запуск в MAX — основной канал

Нужны бот в кабинете MAX и постоянный HTTPS-домен. На сервере задаются `MAX_BOT_TOKEN` (секрет), `MAX_BOT_NAME`, `MAX_ONLY=true`, `PUBLIC_URL`. Токен не отправляйте в чат и не добавляйте в Git. Затем URL приложения настраивается в кабинете бота.

**Пошаговая инструкция и границы проверки: [docs/MAX.md](docs/MAX.md).** Код включает Bridge, серверную HMAC-проверку initData, безопасную привязку профиля, startapp-приглашения, нативную отправку, «Назад», SecureStorage и одноразовое HTTPS-скачивание. Это не означает, что бот уже опубликован.

## Production-конфигурация

`NODE_ENV=production` теперь требует MAX_ONLY, бот, постоянный абсолютный DATA_DIR, настоящий HTTPS PUBLIC_URL, OPERATOR_NAME, SUPPORT_EMAIL, PRIVACY_POLICY_URL, TERMS_URL и DATA_POLICY_VERSION. При неполной конфигурации сервер завершается до открытия БД, а не запускает тестовый сервис публично.

Проверка до запуска: `node --env-file=.env scripts/preflight.js` или `npm run preflight` при уже заданном окружении. Команда не печатает токен и не объявляет продукт production-ready: проверяются настройки, не доступность документов или реальный бот. `/readyz` проверяет БД и права каталога данных (200/503, без раскрытия путей); Docker использует его для healthcheck. В production добавляется HSTS.

Оператор, почта и ссылки на документы отображаются в UI. Версия DATA_POLICY_VERSION входит в версии согласия; после изменения старые записи не переписываются автоматически, требуется новое подтверждение. В разработке остаются честно обозначенные тестовые условия. Подробности: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Локальный запуск в браузере

Node.js **22.16+**, Linux для включённого комплекта браузерных тестов.

```sh
npm ci
npm start
# http://localhost:3000
```

Сервер слушает `0.0.0.0`. Переменные: `PORT` (3000), `DATA_DIR` (`./data`), `TRUST_PROXY` (не задана — X-Forwarded-\* не доверяем). .env автоматически не загружается обычным npm start. Данные SQLite создаются автоматически и сохраняются между перезапусками. Каталоги данных, копий и отчётов исключены из Git.

## Полноценная библиотека

**Более подробные разборы:** у всех занятий есть конкретная цель и пояснение к каждому из 108 вариантов. В безопасности добавлены вопросы проверки, изменённые обстоятельства и ограничения; в практике — самопроверка без экзамена. Пояснения к выбранным ответам появляются после ответа обоих участников.

**36 сценариев, 6 подборок:** деньги и покупки; сообщения без ловушек; тёплые воспоминания; поддержка без контроля; удобный телефон; связь и приватность. На главной представлены все направления, а не только безопасность. В каталоге добавлены подборки и время до 5/6 минут. У практики — пошаговые действия, у разговоров — необязательные дополнительные вопросы, у безопасности — действия на случай уже произошедшего. Содержание и границы проверки: [docs/SCENARIOS.md](docs/SCENARIOS.md).

## Личный выбор занятий

В каталоге есть поиск по названию, описанию и теме (без отправки поискового запроса на сервер), фильтры «Избранное» и «Ещё не пробовали». Кнопка «На потом» сохраняет историю в личном профиле; подборка появляется на главной и доступна на ваших устройствах. Близкий её не видит. Список включён в личный экспорт и удаляется с профилем. Никаких обязательных планов, сроков или уведомлений близкому.

## Что реализовано

- Пространство для двух участников, приглашение по случайной ссылке и её отзыв.
- 36 авторских занятий: 14 по безопасности, 11 семейных разговоров, 11 практических занятий с телефоном. Экспертная вычитка ещё нужна.
- Режим одного телефона и двух устройств. В дистанционном режиме чужие ответы скрыты до взаимного выбора; состояние обновляется каждые 4 секунды.
- История, варианты действий, объяснение, вопрос для разговора, сохранение прогресса и повторное прохождение.
- Разные окончания: семейные истории завершаются благодарностью без обязательной договорённости; обучающие занятия тоже можно завершить без неё. На двух устройствах завершение без договорённости отмечает занятие законченным у обоих после явного подтверждения инициатором; неподтверждённое предложение удаляется.
- Общая памятка; печать в обычном браузере, не в MAX. На двух устройствах договорённость сохраняется только после согласия двух профилей с одной версией текста; правка сбрасывает согласия, устаревшие изменения отклоняются HTTP 409.
- Черновик в sessionStorage текущей вкладки до отправки; переживает обновление, не передаётся близкому и удаляется при выходе, закрытии вкладки, отмене или завершении открытого занятия.
- Добровольные предложения повторить истории безопасности: 3 дня после первого завершения, 10 после второго, 30 после третьего и следующих. По умолчанию выключены; это подсказки на главной, **не push-уведомления**. Настройка личная, не управляется близким.
- Крупный текст, клавиатурная навигация, фокус в диалогах, skip-link, reduced motion; исправлен контраст по результатам автоматических проверок.
- Браузерная Speech Synthesis для готовых историй и разборов. Голос зависит от устройства, некоторые производители используют сетевые сервисы. Не записываем аудио и не озвучиваем пользовательский свободный текст.
- Одноразовый код восстановления, скачиваемая памятка, отзыв прежнего доступа после восстановления и **серверный отзыв ключа при выходе**.
- Экспорт своих данных, изменение имени, удаление профиля, удаление пространства последним участником.
- Техническая запись версии/даты согласия пилота; в MAX отдельная версия `pilot-data-max-v1` с привязкой идентификатора аккаунта. Для старых профилей предлагается принять согласие заново. Это не замена юридическим документам оператора.
- Online backup SQLite, проверяемое восстановление в пустой каталог, healthcheck, корректное завершение по SIGTERM/SIGINT.

Нет таймеров, жизней, оценок, рекламы, аналитических трекеров, доступа к контактам, геолокации, микрофону и камере.

## Проверка двумя людьми

1. На первом устройстве нажмите «Начать вместе», укажите имя/псевдоним и сохраните личный код.
2. Из «Наша пара» отправьте близкому приглашение. Не публикуйте его в открытых чатах.
3. Близкий открывает ссылку, создаёт свой профиль и сохраняет **свой** код.
4. Выберите занятие и режим «Каждый на своём устройстве». Второй участник нажимает «Продолжить занятие».
5. Прочитайте историю и ответьте каждый самостоятельно; обсудите её обычным звонком.
6. Предложите договорённость и подтвердите одну версию отдельно на обоих устройствах — либо явно завершите занятие без неё.

Для второго телефона нужен доступный обоим HTTPS-адрес, не localhost. В режиме одного телефона участники договариваются устно; приложение не проверяет независимую личность двух людей на одном устройстве.

## Восстановление и приватность

В веб-режиме ключ профиля находится в localStorage, в поддерживаемом MAX — SecureStorage с fallback в хранилище WebView; на сервере — только SHA-256 ключей и кодов. Код содержит 128 случайных бит, показывается один раз, может быть скопирован или скачан. При использовании выдаётся новый код, прежние код и ключ доступа перестают работать. Настройки позволяют перевыпустить утраченный код, пока вход ещё действует. В веб-режиме без кода и входа восстановление не предусмотрено. Связанный профиль также доступен через тот же аккаунт MAX. Отзыв устройства здесь не завершает сеанс MAX: при потере телефона завершите его также в мессенджере.

### Мои устройства

До пяти независимых браузерных подключений на профиль. В настройках видны заданные названия, время подключения и последнего обращения (обновляется не чаще раза в минуту). IP, аппаратные идентификаторы и полный User-Agent в этой таблице не сохраняются. Название — подсказка владельцу, не подтверждённая идентификация устройства.

В MAX второй клиент входит через тот же аккаунт MAX; отдельные анонимные формы подключения/восстановления скрыты. Описанный ниже код — механизм браузерного режима.

Чтобы подключить **своё** второе устройство без выхода на первом:

1. На уже подключённом: «Настройки → Мои устройства → Подключить моё другое устройство».
2. На новом: «Есть вход на другом устройстве? Подключить это».
3. Ввести одноразовый код (96 случайных бит), действующий 10 минут, и название нового устройства.

Код не является приглашением близкому. Хранится только его хеш; повторный выпуск отменяет предыдущий. Закрытие окна скрывает код, но не отзывает: есть отдельная кнопка отмены. Успешное подключение потребляет код. При лимите пяти подключений сначала отключите ненужное и получите новый код.

Можно отключить отдельное другое устройство или все остальные. Выход отзывает только текущую сессию. Отзыв, выход и аварийное восстановление отменяют выданные коды подключения. **Личный код восстановления отключает все прежние устройства**, выдаёт новый код восстановления и создаёт одну новую сессию. Привязки почты/телефона пока нет.

Старый единственный ключ автоматически переносится в отдельную сессию при первом запросе. Legacy-значение заменяется неизвестным случайным значением, поэтому после отзыва ключ не может вновь активироваться через миграцию. Названия и время подключений включены в новую техническую версию согласия `pilot-data-v2-devices`; для старой версии в настройках предлагается повторное ознакомление.

Два устройства одного профиля **не считаются двумя людьми**: в дистанционном занятии у профиля один ответ и одно согласие. Независимое решение близкого по-прежнему обязательно. Отзыв закрывает будущие запросы сразу; уже показанный текст, скриншоты и скачанные файлы удалить с чужого устройства невозможно.

API проверяет принадлежность каждой сессии паре, валидирует входные данные, экранирует HTML и ограничивает размер/частоту запросов. Восстановление ограничено пятью запросами на IP за 15 минут, шестой возвращает 429 с Retry-After. Подключение устройства — не более 10 попыток на IP за 15 минут, затем 429. Ограничители сохраняются в отдельной security.sqlite и переживают обычный перезапуск. При недоступной записи защита возвращает 503, не пропускает запрос. Сохраняются HMAC-псевдонимы сети, не исходные IP. Несколько серверов и DDoS требуют отдельных мер. Подробности: [docs/RATE_LIMITS.md](docs/RATE_LIMITS.md). Для прокси задавайте только доверенные IP/CIDR, не произвольное доверие всем заголовкам.

Удаление одного профиля оставляет общие договорённости у близкого. При удалении последнего участника пространство удаляется. Политика хранения производственных копий и порядок выполнения удалений после восстановления архива ещё требуют решения оператора.

## Проверки

```sh
npm run check
npm test          # 69 unit/API/DOM/access/MAX/backup проверок
npm run test:e2e  # 14 сценариев × desktop/mobile Chromium = 28 проверок
npm run test:load # изолированный smoke-прогон 12 пар, 3 пары одновременно
npm run test:edge # 7 интеграционных проверок реального Nginx, локальный стенд
npm run test:all  # всё перечисленное
```

E2E работают в настоящем headless Chromium, в том числе с двумя независимыми браузерными контекстами, скачиванием, восстановлением, отказом сети, 320px-экраном и увеличенным текстом. Браузер и библиотеки доставляются npm-пакетом, без отдельного скачивания с браузерных CDN. Это **не** реальные Android/iOS и **не** Safari/Firefox. Для браузерных Linux-тестов нужен системный tar. Первый `test:edge` дополнительно требует curl, sha256sum, make и C-компилятор: собирается закреплённый Nginx из исходников с проверкой SHA-256, только в игнорируемой .cache. Chromium запускается без OS sandbox только в контролируемой тестовой среде; web security не отключается.

axe-core проверяет выбранные страницы по автоматизируемым правилам WCAG 2 A/AA и 2.1 AA. Нулевые нарушения на этих страницах не означают полное соответствие ГОСТ/WCAG, ручной аудит и скринридеры ещё нужны.

Тесты используют отдельные базы и порты 3218–3235; edge-тесты — временные локальные порты. Восемь MAX E2E используют подменённый Bridge, а не настоящий мессенджер. Playwright оставляет отчёт в `playwright-report`, при ошибках — traces/screenshots в `test-results`; они исключены из Git. Smoke-нагрузка не является проверкой предельной производительности или защитой от атак. GitHub Actions настроен на весь прогон; выполнение в GitHub отдельно не подтверждено.

## Развёртывание и копии

```sh
DATA_DIR=./data npm run backup -- ./backups
DATA_DIR=./data-restored npm run restore -- ./backups/ИМЯ-КОПИИ.sqlite --confirm-stopped
```

Backup можно выполнять при работающей базе, включая WAL. Restore требует остановки приложения и пустого целевого каталога, проверяет SHA-256 и целостность, ничего не перезаписывает. Копии содержат данные и требуют защищённого хранения. Restore теперь аннулирует старые ключи/коды/приглашения и блокирует API до явного подтверждения проверки оператором. Release требует новых запусков MAX и ожидания защитного окна; прежние подписи не восстанавливают доступ. Сверка удалённых после даты копии данных остаётся обязанностью оператора. Порядок выпуска и ограничения браузерных профилей: [docs/RECOVERY.md](docs/RECOVERY.md).

Есть Dockerfile и Compose для одного сервера: Caddy (TLS) → Nginx edge → приложение в изолированной backend-сети. Edge ограничивает частоту/суммарный поток, одновременные запросы, тело и таймауты до Node. Это L7-смягчение, не внешняя защита от насыщения канала. [docs/DDOS.md](docs/DDOS.md). **Docker в текущей среде отсутствует — сборка и реальный TLS ещё не проверены.** Инструкции, ограничения, пример расписания и порядок отката: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

### Автоматические шифрованные копии

В Compose предусмотрен `backup-worker`: AES-256-GCM, online snapshot с WAL, проверка расшифровкой до ротации, статус и отдельный healthcheck. Требуется приватный файл ключа `BACKUP_KEY_HOST_FILE`; создание и запуск — [docs/ENCRYPTED_BACKUPS.md](docs/ENCRYPTED_BACKUPS.md). Внешнее хранилище и оповещения должны быть реально настроены оператором, локальный том их не заменяет. `npm run backup:encrypted`, `backup:daemon`, `backup:health`, `backup:decrypt` доступны для прямого Node-развёртывания.
