# Рядом — чек-лист готовности

Обновлено: **5 ноября 2026 года**, после большого блока реализации и полного `npm run test:all`.

**Статус: пилот MAX Mini App с реализованной интеграцией и локальными проверками с подменённым Bridge, но ещё не публичный промышленный сервис.**

`[x]` — реализовано/выполнено с указанной границей проверки. `[ ]` — не выполнено либо требует внешнего подтверждения. Настроенный инструмент не означает уже оказанную услугу или развёрнутую инфраструктуру.

## 1. Совместный продукт

- [x] Пространство для двух близких, имя/псевдоним, приглашение и отзыв ссылки.
- [x] Один телефон с передачей устройства и два устройства с обновлением каждые 4 секунды.
- [x] Независимый выбор, скрытие чужих ответов до выбора обоих на двух устройствах.
- [x] История → ответы → разбор → разговор; продолжение, повтор и отмена.
- [x] Семейные разговоры заканчиваются благодарностью без обязательного правила.
- [x] Обучающие занятия можно закончить без договорённости, сохранив факт завершения и ответы.
- [x] Если договорённость нужна: отдельное согласие обоих профилей на одну версию, сброс согласий при правке, отказ устаревшим изменениям.
- [x] Общая памятка и браузерная печать (не внутри MAX), черновик текущей вкладки до отправки.
- [x] Добровольные предложения повторить истории безопасности на главной: интервалы 3, 10, 30 дней после очередных завершений; по умолчанию выключены.
- [x] Нет таймеров, жизней, оценок, рекламы и скрытого контроля со стороны близкого.
- [ ] Push/бот-уведомления и напоминания вне приложения. Внутренние предложения повторить ими не являются.
- [ ] Доказанная польза и самостоятельная заинтересованность пожилых участников.
- [ ] Решения о плательщике, оплате и коммерческой модели.

Границы: на одном устройстве согласие устное, независимые личности не проверяются. На двух устройствах завершение без договорённости может инициировать один участник после явного предупреждения о завершении у обоих. Для общения используется обычный звонок вне приложения.

- [x] Поиск по каталогу, категории, «Ещё не пробовали», личное избранное и подборка «На потом» на главной. Список хранится отдельно для каждого участника, доступен на его устройствах, входит в экспорт и удаляется каскадно. Запрос поиска обрабатывается локально.

## 2. Контент

- [x] Библиотека расширена с 6 до **36 авторских занятий**: 14 по безопасности, 11 семейных разговоров, 11 практических занятий с телефоном.
- [x] У каждого — история, вопрос, варианты, объяснение и обсуждение; у обучающих — необязательная договорённость. Во всех 11 практических занятиях — шаги, в 11 разговорах — необязательные дополнительные вопросы, в 14 сценариях безопасности — памятка при уже случившемся.
- [x] 36 целей и 108 индивидуальных пояснений, вопросы проверки и изменённые ситуации для всех 14 историй безопасности; добровольная самопроверка всех 11 практик. Пояснения выбранных ответов раскрываются после обоих участников.
- [x] Шесть подборок на главной и в каталоге, сочетание времени/темы/поиска/избранного. Все 36 проходят полный HTTP-цикл, новые типы проверены в UI. [docs/SCENARIOS.md](docs/SCENARIOS.md).
- [x] Каталог и фильтрация по трём темам; автоматическая проверка структуры и уникальности контента.
- [ ] Экспертная вычитка психологом и специалистом по ИБ.
- [ ] Проверка понятности языка людьми 60+.
- [ ] Формальная методология и подтверждённые источники для таксономии красных флагов.
- [ ] Регулярный выпуск новых историй и редактор контента.

Количество историй выполнено, качество и эффективность этим не доказаны.

- [x] Встроены три сгенерированные редакционные иллюстрации в WebP, обновлены главная и стиль диалогов. Отдельный E2E проверяет загрузку артов, доступное имя окна, горизонтальное переполнение, прокрутку к кнопке и axe окна знакомства на desktop/mobile.

## 4. Доступ, данные и безопасность

- [x] Случайный ключ профиля и одноразовый код восстановления, только хеши на сервере.
- [x] Восстановление сохраняет пару и прогресс, выдаёт новый код и отзывает старый доступ.
- [x] Выпуск/скачивание кода, экспорт данных без ключей и скрытых чужих ответов.
- [x] Выход отзывает текущую браузерную сессию **на сервере**, а не только удаляет ключ из браузера; другие свои устройства остаются подключёнными.
- [x] Проверка принадлежности занятий паре, валидация, экранирование HTML, защитные заголовки и постоянные лимиты API/восстановления/подключения. Шесть новых тестов, включая реальный рестарт, два процесса и fail-closed HTTP 503. Исходные IP не сохраняются, сетевые ключи псевдонимизированы.
- [x] Удаление профиля/пространства; минимизация данных, нет контактов, геолокации и записи голоса.
- [x] Техническая запись версии и даты согласия пилота; Веб-версия pilot-data-v3-security включает метаданные подключений; MAX-версия pilot-data-max-v2-security также привязку аккаунта. Старым профилям предлагается повторное ознакомление, без выдуманной задним числом записи.
- [x] Личная настройка повторений не включает её близкому и не раскрывает код восстановления.
- [ ] Независимый аудит безопасности.
- [x] До пяти независимых браузерных подключений, список, название и отзыв одного или всех остальных устройств.
- [x] Одноразовый код подключения своего устройства: 10 минут, только хеш на сервере, ограничения попыток, отмена/перевыпуск.
- [x] Миграция старого ключа без повторной активации после отзыва; два устройства одного профиля не обходят согласие близкого.
- [ ] Юридически утверждённые согласия, сроки хранения, очистка неактивных профилей и архивов.
- [ ] Промышленный процесс защиты от перебора, реагирования и сверки удалений/отзывов после отката БД.

Границы: в веб-режиме без входа и кода восстановление невозможно; связанный профиль доступен также через тот же аккаунт MAX. Отзыв ключа здесь не завершает сеансы самого MAX. Общие договорённости остаются у напарника после удаления одного профиля. Лимиты запросов постоянные, в отдельной security.sqlite, общие для процессов на одном локальном файле. Это не многосерверная/DDoS-защита. [docs/RATE_LIMITS.md](docs/RATE_LIMITS.md).

## 5. MAX — основной канал

- [x] SDK window.WebApp, серверная проверка HMAC initData, возраст/дубликаты/replay, токен только на сервере.
- [x] Связь MAX ID с профилем после согласия; существующий браузерный профиль — только после отдельного подтверждения. Несовпадение аккаунта блокирует также фоновое чтение данных.
- [x] Подписанный start_param для приглашений, max.ru/bot?startapp, shareMaxContent.
- [x] BackButton, SecureStorage с fallback, viewport/safe area, closing confirmation, best-effort ScreenCapture.
- [x] Нативное JSON-скачивание по HTTPS-адресу на 60 секунд, одноразовое/отзываемое, без bearer в URL. В web MAX ссылка на скачивание открывается внешним браузером через openLink; копирование кода вместо Blob, печать только в обычном браузере.
- [x] MAX_ONLY блокирует обычную регистрацию/присоединение; браузерный режим сохранён для разработки.
- [x] 5 unit/API проверок MAX + 8 Chromium E2E с подменённым Bridge. Инструкция [docs/MAX.md](docs/MAX.md).
- [ ] Бот/кабинет владельца, токен/домен, реальная регистрация и публикация/модерация.
- [ ] Приёмка в настоящих клиентах MAX Android/iOS/web, включая подпись реального initData, диплинки, хранилище и скачивания.

Открытие preview не равно запуску внутри MAX. Telegram не входит в текущий целевой релиз. Кабинет, размещение и реальные клиентские тесты требуют участия владельца.

- [x] Production fail-fast: MAX/HTTPS/диск/контакты оператора/ссылки и версия документов проверяются до запуска, без секретов в диагностике. UI показывает настройки оператора и поддержки, а не фиксированные пилотные заглушки.
- [x] Изменение версии документов требует повторного согласия; production HTTP-тест подтверждает сохранение старой записи до подтверждения и обновление после рестарта.
